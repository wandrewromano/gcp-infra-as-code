# 007 — Solution: count / for_each

## What this creates

- Three `google_storage_bucket`s — `dev`, `staging`, `prod` — from a
  single `resource` block with `for_each = var.bucket_environments`.

## Why for_each over count here

Both `count` and `for_each` create multiple instances of a resource
from one block. The difference is *how Terraform tracks which
instance is which*:

- `count` indexes instances numerically: `0`, `1`, `2`. Terraform
  identifies them by position in the list.
- `for_each` (over a set or map) indexes instances by **key**:
  `"dev"`, `"staging"`, `"prod"`. Terraform identifies them by value,
  not position.

That difference matters the moment the input list changes. Remove
`"staging"` from the middle of a `count`-based list of three
environments, and Terraform sees: index `1` used to be `"staging"`,
now it's `"prod"` — so it plans to **destroy and recreate** what was
index `1` and `2`, even though `"prod"`'s bucket never actually
needed to change. With `for_each`, removing `"staging"` from the set
just removes the `"staging"`-keyed instance; `"dev"` and `"prod"`
aren't touched at all, because their keys never changed.

## Why this specific example (buckets, not something with more moving parts)

Same reasoning as [018_build_a_module](../018_build_a_module) coming
before the capstone — isolating one new concept (`for_each`) using a
resource type you already know well, instead of learning it and a new
resource type at the same time.

## Things worth noticing

- Referencing a `for_each` resource elsewhere requires the key:
  `google_storage_bucket.this["dev"]`, not
  `google_storage_bucket.this[0]` — there is no positional indexing
  once you're using `for_each`.
- The output uses a **for expression** —
  `{ for env, b in google_storage_bucket.this : env => b.url }` — to
  turn the resource's per-instance map into a plain output map. This
  is the standard way to "flatten" a `for_each` resource's results
  into something readable.
- `for_each` requires a set or map with **known keys at plan time** —
  you can't `for_each` over something whose keys are only knowable
  after another resource is created (e.g. IDs generated by GCP). If
  you hit that limitation, `count` is sometimes the only option, or
  you restructure so the keys are known upfront.
